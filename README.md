# AutoSalesBot

ANALINK の需要を測るための、**リスト集め**と**メール送信・フォーム送信**の仕組みです。
SNS の DM は扱いません（規約で自動送信ができないため）。

外部ライブラリは使いません。Python 3.9 以上があれば動きます。

## できること

1. 候補の会社・店（公式サイトのURL）を**自動で集める**（地図のオープンデータ、Web検索）。CSV でも入れられる
2. 公式サイトを数ページだけ見て、**サイトに公表されているメールアドレス**を集める
3. 「営業メールお断り」と書いてある会社を自動で外す
4. 人が確認して承認した相手にだけ、1社1通ずつ送る（1日の上限つき）
5. アドレスが無い会社には、**公式サイトのお問い合わせフォーム**から連絡する
   （普通のフォームは承認後に自動で送り、CAPTCHA 付きなどは人がブラウザで送る）
6. 返信を取り込む。「不要」は停止リストへ、番号（1〜4）は集計へ、宛先不明は除外へ

## 使い方

```bash
python3 -m autosales init
```

`.env` ができるので、送信者の情報（会社名・担当者・住所・メール）と SMTP の設定を書きます。
送信者の情報が空のままだと送信できません。

### 運用前の設定確認

```bash
python3 -m autosales doctor
python3 -m autosales doctor --json
python3 -m autosales doctor --require draft
```

送信者・ひな形・SMTP・IMAPを、リサーチ／下書き／メール送信設定／返信受信設定の段階ごとに確認します。
設定値や認証情報は出力せず、ネット接続・DB作成・DB移行も行いません。診断だけなら終了コード0、
`--require research|draft|email|replies` を付けると、その段階が未準備の場合は終了コード1です。
独自のひな形は `--template 名前` で指定でき、複数指定もできます。

`sender@example.invalid` などのダミー送信元は下書き用として許容し、実配信設定は未準備にします。
`email_ready` や `replies_ready` は設定形式の確認結果であり、ログイン・到達・返信処理の成功を意味しません。
外部SMTPの `none` は準備済みと判定せず、`ssl` または `starttls` を必要とします。

送信元情報の到着前は、隔離した `ASB_HOME` にダミーの会社名・担当者・住所と
`sender@example.invalid` を設定して下書きを確認できます。SMTP・IMAPは空欄のままにします。
実情報へ置き換えた後は同じ `ASB_HOME` で `doctor --require email` と
`doctor --require replies` を実行し、送信元から下書きを再生成してください。
診断は送信コマンドの代行や接続テストではありません。実際の到達・返信処理は、
確認用の宛先で別途検証してから営業対象の承認へ進みます。

### 1. 候補を集める

```bash
python3 -m autosales discover osm 大阪市 --segment show
```

```bash
python3 -m autosales discover search "大阪で、ラウンジやキャバクラを複数店舗運営している会社" --segment honbu
```

```bash
python3 -m autosales import seeds.csv
```

- `discover osm <地域名>` … OpenStreetMap から、公式サイトが登録されている店を集めます。無料で、鍵もいりません。
  同じサイトの店は1社にまとめ、店舗数を数えます。`--kinds` で種類を選べます
  （`bar, nightclub, pub, events_venue, music_venue, karaoke, restaurant`。既定は `bar,nightclub,events_venue,music_venue`）。
- `discover search "<探したい相手>"` … Claude Code（`claude` コマンド）に Web 検索をさせて、運営会社の公式サイトを探します。
  この端末に Claude Code が入っていて、ログイン済みであることが条件です。数分かかります。`--limit` で最大件数（既定 20）。
- `import <CSV>` … 手で作ったリストを入れます。`seeds.example.csv` が見本です
  （列は `会社名, サイト, エリア, 業態, 店舗数, 層, メモ`。UTF-8 でも Excel の Shift_JIS でも読めます）。

どの入れ方でも、ポータルサイトや SNS の URL は入りません。**入れるのは、その会社・店の公式サイトだけ**です。
`--segment`（層）は送り分けと集計に使います（例: `honbu` = 複数店舗の運営会社、`show` = ショーを毎日やる店）。

Claudeが利用上限・ログイン切れ・CLI不在・無出力の時間切れになった場合に、地図検索へ切り替えることもできます。
地域と種類の両方を明示します。

```bash
python3 -m autosales discover search "大阪でラウンジを複数店舗運営している会社" \
  --segment honbu --limit 3 \
  --fallback-osm-area 大阪市 --fallback-osm-kinds nightclub,music_venue \
  --fallback-segment show
```

代替経路で得られるのは地図登録の店舗候補です。元の会社検索と同条件ではないため、業態・運営会社を確認してください。
元の `honbu` 区分は引き継がず、代替用の層を省略した場合は空欄で登録します。取得上限は代替経路にも適用します。
検索結果0件、不正JSON、途中結果を含む失敗、CLI引数の誤りでは切り替えません。
地図APIが利用できなければ理由を表示して終了し、成功したようには扱いません。

### 2. アドレスを集めて、確認する

```bash
python3 -m autosales crawl
```

```bash
python3 -m autosales review
```

`data/review.csv` が出ます。掲載ページを開いて確かめ、「判定」列に `ok` か `ng` を入れます。

```bash
python3 -m autosales approve --csv data/review.csv
```

注意の印が何も付いていない連絡先をまとめて承認するなら `approve --unflagged`。

### 3. 送る

```bash
python3 -m autosales send --template honbu --segment honbu
```

`--live` を付けない限り送りません。`outbox/` に下書き（.eml）が出るので、中身を確かめます。

```bash
python3 -m autosales send --template honbu --segment honbu --live
```

層が混ざっているときは `--segment` を必ず指定します（1社1通で送り直せないため、文面の取り違えを防ぎます）。

### 4. フォームで連絡する（アドレスが無い会社）

`crawl` は、公式サイトのお問い合わせフォームも探して、次の3つに分けます。
前からリストにある「アドレスなし」の会社は、`crawl --recrawl` で読み直すとフォームが入ります。

| 分け方 | どんなフォームか | どう送るか |
|---|---|---|
| 自動 | 問い合わせ用だと分かり、必須の欄の意味がすべて分かり、CAPTCHA などが無いフォーム | 人が承認したあと、`form send` が送る |
| 人が送る | CAPTCHA・迷惑判定の仕組みがある、JavaScript で送る作り、外部のフォームサービス、必須の欄に入れる値が決められない、問い合わせ用か確かめられない、予約などと共用らしい | `form assist` の画面を見ながら、人がブラウザで送る |
| 送らない | 予約用・求人応募用・資料請求用のフォーム、「営業目的ではない」ことの確認を求めるフォーム、送信先が robots.txt で禁止 | 送らない |

迷うフォームは、自動にせず人に回します。公開されるコメント欄・口コミ欄は、フォームとして扱いません。

```bash
python3 -m autosales form review
```

`data/form_review.csv` が出ます。自動で送るものは、フォームのページを開いて、問い合わせ用のフォームであることと、
「入力の内容」（どの欄に何を入れるか）が合っていることを確かめ、「判定」列に `ok` か `ng` を入れます。
「照合」列は消さないでください（書き出したあとにフォームが変わっていないかを確かめるのに使います）。
照合には警告・送り方も含みます。古い版で作成したCSVや警告が変わったCSVは受け付けないため、
`form review` で書き出し直してください。巡回で警告が変わった既承認フォームも確認待ちに戻ります。

```bash
python3 -m autosales form approve --csv data/form_review.csv
```

```bash
python3 -m autosales form send --template honbu_form --segment honbu
```

`--live` を付けない限り送りません。`outbox/` に、欄ごとの入力内容と本文が出ます。

```bash
python3 -m autosales form send --template honbu_form --segment honbu --live
```

人が送るフォームは、補助画面を開きます。1社ずつ、フォームへのリンクと、貼り付ける内容（コピーのボタン付き）が出ます。
自分でフォームを開いて送り、「送った」「あとで」「送らない」を押します。

```bash
python3 -m autosales form assist --template honbu_form --segment honbu
```

補助画面は自分のPCの中だけで動き、相手のサイトには何も送りません。「送った」を押した分は、1日の上限と1社1回に数えます。

### 5. 反応を見る

```bash
python3 -m autosales replies
```

```bash
python3 -m autosales stats
```

そのほか: `preview`（文面を画面で見る）、`suppress <アドレス|ドメイン|URL>`（停止リストに入れる）、
`unrefuse <会社ID>`（「営業お断り」の誤検知を、検知した文を見たうえで解除）、`export`（全体をCSVに出す）。

## 送ってよい相手の決まり

送信の宛先は `db.sendable_contacts()` だけが決めます。次のすべてを満たす相手です。

- 公式サイトに公表されていたアドレス（掲載ページのURLを記録）
- そのサイトに「営業メールお断り」の類が見つからなかった
  （お断りのサイトに載っていたアドレスは、別のサイトで見つかっても送りません）
- 人が確認して承認した
- 停止リスト（アドレス・ドメイン・親ドメイン）に無い。その会社の誰かから停止の連絡を受けていない
- その会社にまだ1通も送っていない（届いたかどうか不明の1通も「送った」に数えます）

根拠は特定電子メール法 3条1項4号（自分のアドレスを公表している団体・営業を営む個人には、
同意なしで送れる。ただし公表とあわせて広告メールを拒否している場合を除く）です。
署名（送信者名・住所・停止の連絡先）は自動で付き、ひな形からは消せません。

**アドレスを崩して書いているページ**（`info[at]…`、「＠を半角に直して」、文字参照など）からは拾いません。

次の場合は注意の印が付き、`approve --unflagged` では承認されません（人が見て判断します）。
求人用らしい / 個人情報窓口らしい / フリーメール / サイトと別ドメイン / 見出しや電話番号とつながっていた /
アドレスの途中にタグがあった / お問い合わせページを読めていない / ページが長すぎて最後まで読めていない。

## フォームで連絡するときの決まり

相手は `db.sendable_forms()` だけが決めます。メールと同じ決まりに、次を足しています。

- **メールで送れる会社には、フォームでは送りません**（確認待ち・承認済みのアドレスがある会社はメールを優先）。
  メールとフォームを合わせて1社1回、1日の上限も共通です
- **CAPTCHA や迷惑判定の仕組みは回避しません。** そういうフォームは人が送ります
- 「営業お断り」の表示があるサイトには送りません。送る直前にもページを読み直して確かめます
- 送る直前のフォームが、承認したときと違う作り（欄・見出し・選択肢・隠し項目・送信先が変わった）なら送らず、
  確認待ちに戻します。確認画面に「営業お断り」や CAPTCHA があった場合も、最後の送信はしません
- 確認画面では、元の本文を保持するフォームと送信ボタンを特定できる場合だけ次へ進みます。
  完了ページの別フォームや戻るボタンは操作しません。完了後に空の入力欄が出るなど成否が不明な場合は再送しません。
- 送信前にページを開けないなどの見送りは送信件数の枠に数えず、後続の候補を確認します。
  日次上限・今回の上限は維持し、見送り数を結果に表示します。
- 予約用・求人応募用・資料請求用のフォーム、送信先が robots.txt で禁止されているフォームには送りません
- 種別を選ぶ欄は、「ご提案」「お取引」の類 →「その他」→ 一般の問い合わせ、の順で選びます。
  「予約」「採用」などしか無ければ、人が送る方に回します。選択肢の名前を確かめられないラジオボタンも、人に回します
- 欄の意味は、その欄の見出しで決めます。見出しがあるのに意味が分からない欄は、空のまま送ります（必須なら人に回します）
- 人に見えない欄（迷惑対策の隠し欄）は、空のまま送ります。同意のチェックは、個人情報の取り扱い・規約への同意だけに入れます
- 同じ公表アドレスを載せている別の会社には、メールとフォームの両方で届かないようにします
- 自動で送って「送れていない」と分かったフォーム（こちらの入力が残ったまま入力画面に戻された、エラーの表示がある、
  確認画面を自動で進められない）は、人が送る方に回し、自動には戻しません
- **送れたかどうかを決められないときは「届いたか不明」として、もう一度は送りません**（2通届くのを避けるためです）。
  送信後に回線が切れた、完了の表示を確認できない、完了の表示と一緒に入力フォームがもう一度出た、などです。
  `export` のCSVで「届いたか不明」の会社を見られるので、気になるものは相手のサイトを見て判断してください
- 人が「送らない」と決めたフォームは、巡回し直しても戻しません
- 本文には、メールと同じ署名（送信者名・住所・停止の連絡先）が必ず付きます。差出人を偽ることはしません
  （`User-Agent` も `CRAWL_USER_AGENT` のままです）

次の場合は注意の印が付き、`form approve --unflagged` では承認されません。
種別を選んでいる / 同意のチェックを入れる / 意味の分からない任意の欄がある / メールアドレスの欄がない /
同じページに問い合わせフォームが複数ある。

フォームからの送信は、特定電子メール法の「電子メール」（SMTP と SMS）には当たらないと読む解説が多いものの、
**国がそう明言した資料は見つかっていません**（受け手の側でメールに変換される点をどう見るかは決着していません）。
そのため、メールと同じ決まり（送信者の表示、停止の受付、お断りの尊重）で運用する作りにしています。
本格的に使う前に、弁護士に確認してください。

フォームで連絡した会社からの返信は、差出人のドメインがその会社のサイトと同じとき
（または、サイトに載っていたアドレスからのとき）に、その会社の返信として取り込みます。
フリーメールからの返信は結び付けられないので、「不要」の連絡は `suppress` で手で入れてください。
フォームに送ると返ってくる**受付の控え（自動返信）は、返信にも停止にも数えません**
（控えに貼られたこちらの文面の「不要」や番号を、相手の返事と取り違えないためです）。

設定（`.env`）: フリガナが必須のフォームには `SENDER_PERSON_KANA`、郵便番号が必須のフォームには `SENDER_ZIP` が要ります。
姓と名が別の欄のフォームのために、`SENDER_PERSON` は「山田 太郎」のように空白で区切ってください。
足りない設定があるフォームは、設定するまで送りません（理由が表示されます）。

## 巡回の決まり

- 最初に robots.txt を読み、禁止されていれば1ページも読みません。転送先も1つずつ確かめます
- 1サイト最大8ページ。お問い合わせ → 会社概要 → 規約 の順に見ます。同じサイトへは2秒以上あけます
- フレームで組まれた古いサイトは、フレームの中身のページも読みます（最大3ページ。上の8ページとは別枠）
- 入力欄の中の薄い文字（placeholder）に書かれた「営業お断り」も読みます
- 公式サイトの外には出ません。別のドメインへ転送されるサイトは「対象外」にして、人の確認に回します

## 送信の決まり

- 1日の上限（`DAILY_LIMIT`、既定20通）は、`--limit` や同時実行でも超えません。送信は同時に1本だけ動きます
  （メールの送信、フォームの自動送信、補助画面のどれか1つ）
- サーバーが「宛先が存在しない」と答えたときだけ、その連絡先を宛先不明にします。
  別の日にも断られた宛先も宛先不明にします
- 送信元アドレスの拒否や認証の失敗は設定の問題なので、1通目で止めます
- 続けて2社に断られたときも、こちらの設定の問題を疑って止めます。このとき付けた宛先不明の印は取り消します
- 送っている途中で回線が切れた1通は「届いたか不明」として記録し、再送しません

## 文面

`templates/honbu.txt`（運営会社の本部向け）と `templates/show.txt`（ショーをやる店向け）。
フォーム用は `honbu_form.txt` と `show_form.txt`（書き出しと返信の頼み方だけが違います）。
1行目が件名、2行目以降が本文です。差し込みは `{{会社名}}` `{{送信者会社名}}` `{{担当者名}}`
`{{提供開始時期}}` `{{デモURL}}` `{{エリア}}` `{{業態}}`。値が空の差し込みがあると、送る前に止まります。

## 置き場所

- `data/` … データベースと確認用CSV（店の連絡先が入るので Git に入れません）
- `outbox/` … 下書き
- `.env` … 送信者の情報と、SMTP・IMAP のパスワード（Git に入れません）

## データの出どころ

- OpenStreetMap のデータは © OpenStreetMap contributors、ODbL です。リストを外に公開・配布する場合は表示が必要です。
- ポータルサイト（naramori など）からの自動収集は入れていません。利用規約で商業目的の利用が禁止されているためです。

## テスト

```bash
python3 -m unittest discover -s tests
uvx ruff==0.17.5 check --config ruff.toml autosales scripts tests
uvx ruff==0.17.5 format --config ruff.toml --check autosales scripts tests
```

外にはつながず、手元に立てた仮の Web サーバーとメールサーバーで、取り込みから返信の処理までを通しで確かめます。
フォームの自動送信は、仮のサーバーでしか試していません。実際のサイトへは、1件ずつ結果を見ながら始めてください。

### ワークフローのドライテスト

架空の4社を使い、CSV取り込み → 公式ページの巡回 → メール・通常フォーム・CAPTCHA・営業拒否の分類 →
確認CSVの出力と承認取り込み → メールとフォームの下書き作成までを、実際のCLI処理で再現します。

```bash
python3 scripts/dry_run_smoke.py --output-dir /tmp/analink-dry-run-evidence
```

既定は下書きまでです。メール・フォーム各1件の下書きを作り、SMTP接続・フォームPOST・本送信記録がすべて0件であること、
件名と本文に差し込み残りがないことを検証します。`.env` や運用DBは読みません。一時DBとlocalhost上の架空サイトを使い、
DNS・ソケット接続はこのテストが立てたサーバー以外を拒否します。保存先はリポジトリの外を指定してください。

送信処理と返信処理も確認したい場合は、次を使います。

```bash
python3 scripts/dry_run_smoke.py --output-dir /tmp/analink-dry-run-evidence --local-delivery
```

同じドライテストに続けて、別の段階でlocalhostの仮SMTPと仮フォームへ各1件を送ります。
再実行時の重複0件、番号返信1件、停止1件、CAPTCHAの手動待ち1件も確認します。
この段階で使う `--live` は仮サーバーに限られ、外部宛先には届きません。返信は架空メールを処理関数へ直接渡すため、IMAPには接続しません。

実行ごとに表示される `run-*` ディレクトリへ、`result.json`（件数と検証結果）、`transcript.log`（CLI実行記録）、
確認用CSV、下書き、`dry-run.sqlite3` を保存します。追加段階を実行した場合は `local-delivery.sqlite3` も保存します。
検索APIによる外部候補収集、実SMTP・IMAP、実サイトへの送信、ブラウザーによる手動送信は、このテストの対象外です。

## DBの更新

起動時に `autosales/migrations/v001_forms.py` をトランザクション内で適用し、
`PRAGMA user_version=1` として管理します。既存のメール送信・停止・返信履歴を保ったまま、
フォームと共通送信履歴のテーブル、返信の会社IDを追加します。失敗した場合は変更を戻して起動を止めます。
旧版の未バージョン管理フォームDBも、記録を保持したまま移行します。

downgrade は空のテストDBだけに対応します。業務データがあるDBは拒否し、
送信履歴を削除して再送可能になる状態を防ぎます。本番DBの巻き戻しには使わないでください。

引き継ぎ状態・検証証跡・次の作業は [SCRATCHPAD.md](SCRATCHPAD.md) に記録しています。
